تطبيق ويب عربي (RTL) لإدخال درجات الطلبة وتدقيقها واعتمادها واستخراج الماستر شيت والتقارير، يعمل على الحاسوب والهاتف ويمكن تثبيته كتطبيق من المتصفح (PWA). مجاني بالكامل: **Supabase** لقاعدة البيانات وتسجيل الدخول، و**GitHub Pages** لاستضافة التطبيق.

## المميزات

| المجال | التفاصيل |
|---|---|
| **الأقسام** | الأقسام الخمسة مُعدّة مسبقاً: التخدير (صباحي + مسائي)، الأشعة والسونار (صباحي + مسائي)، صناعة الأسنان، صحة المجتمع (صباحي + مسائي)، التجميل والليزر. يمكن إضافة أقسام أخرى لاحقاً. |
| **الهيكل الدراسي** | سنة دراسية (2025-2026، 2026-2027 …) ← قسم ← مرحلة ← دراسة صباحية/مسائية ← فصل أول/ثاني. |
| **الطلبة** | إضافة الأسماء **بالنسخ واللصق** من Excel أو Google Sheets أو Word، مع **تسلسل ثابت لا يتغير**، واكتشاف الأسماء المكررة تلقائياً (حتى مع اختلاف الهمزة والتاء المربوطة). |
| **الخطة الدراسية** | لكل قسم خطة دراسية (المواد لكل مرحلة وفصل مع الساعات النظرية والعملية والوحدات). الخطط الرسمية 2025-2026 لأقسام **التخدير والأشعة والسونار وصناعة الأسنان وصحة المجتمع (المراحل الأربع، 218 مادة)** مضافة مسبقاً، وتُضاف أي خطة أخرى **بلصق جدول المواد من ملف Word مباشرة**. تُستورد مواد كل سنة دراسية من الخطة **بضغطة زر** مع توزيع الدرجة المناسب تلقائياً. |
| **المواد وتوزيع الدرجة** | السعي 40% (قابل للتغيير إلى 30%)، العملي النهائي 25% (أو بدون عملي)، والامتحان النهائي يُحسب تلقائياً (35% أو 70%). يمكن تقسيم السعي إلى نظري + عملي كما في السجل الحالي (25 + 15). |
| **إدخال الدرجات** | جدول يشبه Excel: التنقل بالأسهم وEnter، **لصق عمود كامل من Excel**، حفظ تلقائي، تمييز القيم الخاطئة والناقصة، حساب المجموع والتقدير فوراً، حالات خاصة (غائب/محروم/مؤجل) بكتابة «غ» أو «ح» أو «م». |
| **المواد التقويمية (الوزارية)** | خيار «تقويمية (وزارية)» لكل مادة: سعي 40 من القسم والكلية + امتحان نهائي وزاري 60، ويُشترط للنجاح الحصول على **30 من 60** في الامتحان النهائي (قابل للتعديل) إضافة إلى درجة النجاح. مثال: سعي 35 + نهائي 29 = 64 لكن الطالب **راسب**. يُطبق الشرط في الدور الثاني والماستر شيت والنتائج. يمكن تعليم المادة كتقويمية في الخطة الدراسية لتُستورد بهذا التوزيع تلقائياً. |
| **الدور الثاني** | للطلبة غير الناجحين في الدور الأول (أو الغائبين): **السعي الفصلي ثابت** ويُعاد إدخال درجة الامتحان النهائي فقط، بدورة تدقيق واعتماد مستقلة. يمكن تحديد سقف لدرجة الدور الثاني من الإعدادات (لا يُطبق على المؤجلين). |
| **فتح وغلق الإدخال** | بضغطة زر للكلية كلها أو لقسم محدد — صلاحية **مدير النظام والعميد ومعاون العميد** فقط، ومطبق على مستوى قاعدة البيانات. |
| **دورة التدقيق** | مسودة ← إرسال إلى اللجنة ← إعادة للتعديل مع ملاحظة ← اعتماد. تعديل القائمة المعتمدة يتطلب ذكر السبب ويُسجَّل. |
| **الماستر شيت** | لكل مرحلة وفصل (أو سنوي): لكل مادة **السعي والنهائي والمجموع**، وتحتها **سطر الدور الثاني** لمن امتحن فيه، ثم **مجموع الدرجات** و**المعدل** و**الترتيب** و**النتيجة** (ناجح / مكمل في: … / راسب) و**الملاحظات**، مع إحصائيات كل مادة والأوائل وتوزيع التقديرات. |
| **المعدل والنتيجة** | المعدل **موزون بالوحدات**: Σ(الدرجة × وحدات المادة) ÷ Σ الوحدات (مثال: 80×3 + 70×2 + 90×4 = 740 ÷ 9 = 82.22). درجة النجاح 50 مع **جبر الكسور** (49.5 ← 50). الطالب **مكمل** إذا رسب في مادتين فأقل، و**راسب** إذا رسب في أكثر من ذلك (العدد قابل للتعديل من الإعدادات). |
| **نتيجة الطالب** | صفحة لكل طالب تعرض درجاته في **كل المواد** للفصلين، و**بطاقة نتيجة رسمية للطباعة** (لفصل واحد أو للفصلين معاً) بشعار الكلية ومعلومات الطالب والتقديرات فقط، والنتيجة النهائية، واسم **رئيس القسم** ومكان التوقيع والختم. يمكن طباعة نتائج المرحلة كلها دفعة واحدة (صفحة لكل طالب) مع تصفية الناجحين أو المكملين أو الراسبين. |
| **البحث عن طالب** | بحث سريع بالاسم في كل الأقسام والسنوات. |
| **التقارير** | طباعة رسمية / PDF بترويسة الكلية والشعار والتواقيع، وتصدير **Excel** بنفس تنسيق السجلات الحالية (الماستر شيت + ورقة لكل مادة). تقرير الإنجاز حسب المادة أو التدريسي. |
| **الحسابات** | حساب لكل قسم (مقرر القسم) + حساب عام (العميد) + حسابات التدريسيين واللجنة. **توليد الحسابات من داخل التطبيق** (فردياً أو جماعياً من قائمة أسماء) مع كلمات مرور مؤقتة وبطاقات دخول قابلة للطباعة. |
| **الإعلانات** | يكتب مدير النظام أو العميد أو المعاون (للكلية أو لقسم) ومقرر القسم (لقسمه) إعلانات بثلاث درجات أهمية (عادي، مهم، عاجل)، مع تحديد الفئة (الجميع، التدريسيون، المقررون) وتاريخ انتهاء وتثبيت. يظهر الإعلان المهم والعاجل في **شريط بارز أعلى الصفحات** حتى يُقرأ، وآخر الإعلانات في لوحة المتابعة. |
| **حجب الدرجات بعد الغلق** | عند غلق إدخال الدرجات (للكلية أو للقسم) **تُحجب كل الدرجات عن حسابات التدريسيين** فلا يستطيعون رؤيتها، لأن مهمتهم تنتهي بتسليم الدرجات وما بعدها سري. الحجب مطبق في قاعدة البيانات نفسها، ويمكن إيقافه من الإعدادات. |
| **سجل العمليات** | كل إدخال وتعديل (الدرجة القديمة والجديدة)، إرسال، إعادة، اعتماد، فتح/غلق، دخول وخروج — غير قابل للحذف. |
| **الأمان** | كلمات مرور مشفرة (bcrypt)، صلاحيات على مستوى الصفوف في قاعدة البيانات (RLS)، خروج تلقائي بعد فترة خمول، إجبار تغيير كلمة المرور المؤقتة. |
| **أخرى** | وضع ليلي، تصميم متجاوب للهاتف، تثبيت كتطبيق (PWA)، نسخ احتياطي يومي مشفر، تقريب الدرجات وجدول التقديرات قابلان للتعديل. |

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| **مدير النظام** | كل شيء: الإعدادات، الأقسام، السنوات، كل الحسابات، فتح/غلق الإدخال، تعديل أي درجة. |
| **العميد** (الحساب العام) | الاطلاع والإضافة والتعديل على كل الأقسام، الإعدادات، الحسابات (عدا مدير النظام)، فتح/غلق الإدخال. |
| **معاون العميد** | كل الأقسام، فتح/غلق الإدخال، التدقيق والاعتماد، تعديل الدرجات بعد الغلق، إنشاء حسابات اللجنة والمقررين والتدريسيين. |
| **اللجنة الامتحانية** | الاطلاع على كل الأقسام، تدقيق القوائم وإعادتها أو اعتمادها. لا تعدّل الدرجات. |
| **مقرر القسم** (حساب القسم) | إدارة قسمه فقط: المواد، الطلبة، إسناد التدريسيين، إنشاء حسابات تدريسيي القسم، إدخال الدرجات، الماستر شيت. |
| **التدريسي** | المواد المسندة إليه فقط: إدخال الدرجات وإرسالها إلى اللجنة. |

> عند غلق الإدخال لا يستطيع أحد إدخال أو تعديل الدرجات سوى مدير النظام والعميد ومعاون العميد.

## التشغيل الفعلي (مجاناً) — دليل خطوة بخطوة

**المدة:** 30–45 دقيقة تقريباً. **المطلوب:** حاسوب بمتصفح Chrome أو Edge، وحساب GitHub الحالي.
جهّز ورقة لتدوين ثلاثة أشياء: كلمة مرور قاعدة البيانات، واسم وكلمة مرور حساب المدير، وعبارة تشفير النسخ الاحتياطي.

### المرحلة 1: إنشاء مشروع Supabase (قاعدة البيانات)
1. ادخل إلى https://supabase.com واضغط **Start your project**.
2. اختر **Continue with GitHub** وادخل بحساب GitHub نفسه، ثم اضغط **Authorize supabase**.
3. عند طلب إنشاء منظمة (Organization) اكتب اسماً مثل `Alsiraj Health College`، واختر النوع **Educational** والخطة **Free - $0/month**، ثم **Create organization**.
4. في صفحة **Create a new project**:
   - **Project name:** `exam-committee`
   - **Database Password:** اضغط **Generate a password** ثم **Copy**، واحفظها في مكان آمن (تحتاجها للنسخ الاحتياطي).
   - **Region:** اختر أقرب منطقة متاحة للعراق، ويُنصح بـ **Central EU (Frankfurt)**.
   - اترك الإعدادات المتقدمة (Security options) على الوضع الافتراضي، والمهم أن تبقى خاصية **Data API** مفعّلة على مخطط `public`.
   - اضغط **Create new project** وانتظر دقيقة إلى دقيقتين حتى يكتمل الإعداد.

### المرحلة 2: إنشاء الجداول والصلاحيات
5. افتح المستودع https://github.com/Sofianiq/Exam ثم المجلد `supabase` ثم الملف `schema.sql`، واضغط زر **Copy raw file** (رمز المربعين أعلى يمين الملف).
6. في Supabase افتح **SQL Editor** من القائمة الجانبية، ثم **+ New query**.
7. الصق النص (Ctrl+V) واضغط **Run** (أو Ctrl+Enter).
   - إن ظهر تحذير بأن الاستعلام يحتوي عمليات حذف (destructive operation) فاضغط **Run this query**؛ هذا متوقع، فالملف يعيد إنشاء قواعد الصلاحيات فقط ولا يحذف بيانات.
   - النتيجة المتوقعة أسفل الشاشة: **Success. No rows returned**.
8. لإنشاء حساب مدير النظام امسح محتوى المحرر واكتب السطر التالي، بعد استبدال `YourStrongPassword` بكلمة مرور قوية من اختيارك:
   ```sql
   select public.create_first_admin('admin', 'YourStrongPassword', 'مدير النظام');
   ```
   - اسم المستخدم بأحرف إنجليزية صغيرة وأرقام فقط (3 إلى 32 حرفاً). كلمة المرور 6 أحرف على الأقل، ويُنصح بـ 12 حرفاً فأكثر تجمع الأحرف والأرقام.
   - اضغط **Run**؛ يجب أن يظهر صف واحد فيه رقم تعريف، أي أن الحساب أُنشئ.
   - احذف هذا الاستعلام بعدها من قائمة الاستعلامات المحفوظة لأنه يحتوي كلمة المرور (قائمة ⋯ بجانبه ← **Delete query**).

### المرحلة 3: إعدادات الأمان في Supabase
9. **Authentication ← Sign In / Providers**:
   - أطفئ **Allow new users to sign up** ثم **Save changes**، لأن الحسابات تُنشأ من داخل التطبيق فقط.
   - تأكد أن مزوّد **Email** يبقى مفعّلاً (Enabled)، لأن تسجيل الدخول يتم من خلاله.
10. **Authentication ← Rate Limits**: غيّر **Rate limit for sign ups and sign ins** من 30 إلى **200** ثم **Save changes**. السبب أن أجهزة الكلية تخرج إلى الإنترنت بعنوان IP واحد، والحد الافتراضي (30 محاولة كل 5 دقائق) قد يمنع الدخول وقت الذروة.

### المرحلة 4: نسخ بيانات الربط
11. **Project Settings** (رمز الترس أسفل القائمة) ← **Data API** ← انسخ **Project URL**، وشكله `https://abcdefgh.supabase.co`.
12. **Project Settings ← API Keys** ← انسخ **Publishable key** (يبدأ بـ `sb_publishable_`). إن ظهر تبويب **Legacy API Keys** فيمكنك بدلاً منه نسخ مفتاح **anon public**؛ كلاهما يعمل.
   - ⚠️ لا تنسخ **Secret key** ولا **service_role**، ولا تضعهما في GitHub أبداً.
   - (طريقة بديلة: زر **Connect** أعلى لوحة المشروع يعرض الرابط والمفتاح معاً.)

### المرحلة 5: إعداد GitHub
13. **إنشاء الفرع `main`:** افتح https://github.com/Sofianiq/Exam، واضغط زر الفرع أعلى قائمة الملفات (يظهر عليه `claude/compassionate-mccarthy-91ivmz`)، واكتب `main` ثم اضغط **Create branch main from claude/compassionate-mccarthy-91ivmz**. قد يبدأ تشغيل تلقائي للنشر ويفشل لأن الإعداد لم يكتمل بعد؛ هذا طبيعي فتجاهله.
14. **جعل `main` الفرع الافتراضي:** **Settings ← General ← Default branch** ← زر ⇄ (Switch to another branch) ← اختر **main** ← **Update** ← **I understand, update the default branch**.
15. **إضافة بيانات الربط:** **Settings ← Secrets and variables ← Actions** ← تبويب **Variables** ← **New repository variable**:
   - Name: `SUPABASE_URL` — Value: الرابط من الخطوة 11 ← **Add variable**
   - Name: `SUPABASE_ANON_KEY` — Value: المفتاح من الخطوة 12 ← **Add variable**
   - اكتب الأسماء حرفياً كما هي (أحرف كبيرة وشرطة سفلية).
16. **تفعيل GitHub Pages:** **Settings ← Pages ← Build and deployment ← Source** ← اختر **GitHub Actions**.

### المرحلة 6: النشر والتحقق
17. افتح تبويب **Actions** ← من القائمة الجانبية **Deploy to GitHub Pages** ← زر **Run workflow** ← Branch: **main** ← **Run workflow**.
18. انتظر نحو دقيقتين حتى تظهر علامة ✅ خضراء لمرحلتي **build** و **deploy**.
19. افتح الموقع: **https://sofianiq.github.io/Exam/**
   - ✅ علامة النجاح: صفحة الدخول تظهر **بدون** المربع الأصفر «نسخة تجريبية».
   - ❌ إن ظهر المربع الأصفر فبيانات الربط لم تُقرأ: راجع الخطوة 15 ثم أعد الخطوة 17 (ستجد أيضاً تحذيراً بعنوان **Demo mode** في صفحة التشغيل).
20. ادخل باسم المستخدم وكلمة المرور من الخطوة 8.

### المرحلة 7: تهيئة النظام من داخل التطبيق
21. **الإعدادات:** راجع اسم الجامعة والكلية، ودرجة النجاح (50)، والتقريب، وجدول التقديرات، والسنة الدراسية الحالية (2026-2027 مضبوطة مسبقاً).
22. **المستخدمون ← حساب جديد**، وأنشئ الحسابات التالية:

    | الحساب | الدور | القسم | اسم مستخدم مقترح |
    |---|---|---|---|
    | العميد | العميد | — | `dean` |
    | معاون العميد | معاون العميد | — | `vice` |
    | أعضاء اللجنة الامتحانية | اللجنة الامتحانية | — | `committee1`، `committee2` … |
    | مقرر قسم تقنيات التخدير | مقرر القسم | تقنيات التخدير | `ans.head` |
    | مقرر قسم تقنيات الأشعة والسونار | مقرر القسم | تقنيات الأشعة والسونار | `rad.head` |
    | مقرر قسم تقنيات صناعة الأسنان | مقرر القسم | تقنيات صناعة الأسنان | `den.head` |
    | مقرر قسم تقنيات صحة المجتمع | مقرر القسم | تقنيات صحة المجتمع | `cht.head` |
    | مقرر قسم تقنيات التجميل والليزر | مقرر القسم | تقنيات التجميل والليزر | `cos.head` |

    - بعد كل إنشاء تظهر بيانات الدخول (اسم المستخدم وكلمة مرور مؤقتة): اطبعها من **طباعة البطاقات** أو صدّرها **Excel** وسلّمها لصاحبها. لن تظهر مرة أخرى، ويمكن توليد غيرها من زر 🔑 بجانب الحساب.
    - عند أول دخول يُطلب من كل مستخدم تغيير كلمة المرور المؤقتة.
23. يقوم كل مقرر قسم بما يلي:
    1. **المستخدمون ← إنشاء حسابات جماعية**: الصق أسماء تدريسيي القسم (اسم في كل سطر، ويمكن كتابة اللقب مثل «م.م.» قبل الاسم) ← **إنشاء** ← اطبع البطاقات.
    2. **قسمي** ← اختر المرحلة والدراسة (صباحي/مسائي) ← تبويب **قائمة الطلبة** ← **إضافة طلبة (نسخ ولصق)** ← انسخ عمود الأسماء من Excel أو Google Sheets والصقه ← راجع المعاينة ← **إضافة**.
    3. **الأقسام العلمية ← الخطة الدراسية** (مرة واحدة لكل قسم): إن لم تكن خطة القسم مضافة، افتح ملف المفردات الدراسية في Word وحدد صفوف جدول المواد وانسخها ← **لصق جدول من Word** ← اختر المرحلة والفصل ← **إضافة**.
    4. تبويب **المواد والدرجات** ← اختر الفصل ← **استيراد من الخطة الدراسية** ← **إضافة**، ثم افتح كل مادة من زر التعديل وحدد **التدريسي**. (أو **إضافة مادة** يدوياً: الاسم، والوحدات، وتوزيع الدرجة نظري + عملي = 40/25/35 أو نظري فقط = 30/70، والتدريسي). يمكن استخدام **نسخ مواد** لنقل المواد من الدراسة الصباحية إلى المسائية.
24. يدخل التدريسي ← **موادي الدراسية** ← يفتح المادة ← يُدخل الدرجات أو يلصقها من Excel ← **إرسال إلى اللجنة**.
25. تفتح اللجنة **التدقيق والاعتماد** ← **تدقيق** ← **اعتماد** أو **إعادة للتعديل** مع ملاحظة.
26. عند انتهاء مدة الإدخال: العميد أو معاون العميد ← **التحكم بالإدخال** ← **غلق الإدخال للجميع**.
- **الدور الثاني:** بعد اعتماد قائمة المادة يظهر فيها مفتاح **الدور الأول / الدور الثاني**. في الدور الثاني يظهر الطلبة غير الناجحين فقط مع سعيهم الثابت، ويُدخل التدريسي درجة الامتحان النهائي ← **إرسال إلى اللجنة** ← تعتمدها اللجنة من **التدقيق والاعتماد ← الدور الثاني**.
- **النتائج:** المرحلة ← تبويب **الماستر شيت** ← **نتائج الطلبة (طباعة)** لطباعة نتائج الجميع، أو اضغط اسم أي طالب لعرض درجاته وطباعة نتيجته. حدّد اسم **رئيس القسم** لكل قسم من **الإعدادات ← الأقسام** ليظهر في النتيجة.

### المرحلة 8: النسخ الاحتياطي اليومي (موصى به بشدة)
الخطة المجانية في Supabase لا تتضمن نسخاً احتياطية قابلة للتنزيل، لذلك يتضمن المشروع مهمة ليلية (`.github/workflows/maintenance.yml`) تأخذ نسخة **مشفرة** تُحفظ 30 يوماً، وتُبقي المشروع المجاني نشطاً (يتوقف المشروع المجاني تلقائياً بعد أسبوع دون استخدام).

27. في Supabase اضغط زر **Connect** أعلى الصفحة ← **Connection String** ← **Type: URI** و **Method: Session pooler** ← انسخ الرابط، وشكله:
    `postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`
    - استبدل `[YOUR-PASSWORD]` (مع القوسين) بكلمة مرور قاعدة البيانات من الخطوة 4.
    - استخدم **Session pooler** تحديداً، لأن خوادم GitHub لا تدعم الاتصال المباشر (Direct connection).
    - إن كانت كلمة المرور تحتوي رموزاً مثل `@ # / ? : %` فأعد تعيينها بأحرف وأرقام فقط من **Project Settings ← Database ← Reset database password**.
28. في GitHub: **Settings ← Secrets and variables ← Actions** ← تبويب **Secrets** ← **New repository secret**:
    - `SUPABASE_DB_URL` = الرابط الكامل من الخطوة 27
    - `BACKUP_PASSPHRASE` = عبارة سرية طويلة (مثلاً خمس كلمات إنجليزية عشوائية). **دوّنها على ورق واحفظها**؛ بدونها لا يمكن فتح النسخ.
29. للتجربة: **Actions ← Daily maintenance ← Run workflow**. بعد نجاحه افتح صفحة التشغيل، وستجد في أسفلها تحت **Artifacts** ملفاً باسم `exam-backup-التاريخ` (مشفراً). بعدها يعمل تلقائياً كل ليلة.
30. يوقف GitHub المهام المجدولة في المستودعات العامة بعد 60 يوماً دون أي تحديث للكود ويرسل بريداً بذلك؛ عندها افتح **Actions ← Daily maintenance ← Enable workflow**.

### تحديث النظام لاحقاً (دون فقدان البيانات)
- تحديثات الواجهة تُنشر تلقائياً عند دمجها في `main`، ولا تمس البيانات.
- عندما يتضمن التحديث تغييرات في قاعدة البيانات (مثل هذا الإصدار: الخطة الدراسية، الدور الثاني، اسم رئيس القسم): انسخ محتوى `supabase/schema.sql` الجديد والصقه في **SQL Editor** ثم **Run** — الملف يضيف الجداول والأعمدة الجديدة فقط ولا يحذف أي بيانات.
- الإصدار الثالث (الخطط الدراسية لكل الأقسام، المواد التقويمية، الإعلانات، حجب الدرجات) يتطلب أيضاً إعادة تشغيل `supabase/schema.sql` بالطريقة نفسها؛ تُضاف المواد الجديدة إلى الخطط دون المساس بما عدّلته سابقاً.
- في قاعدة بيانات أُنشئت قبل الإصدار الثاني: افتح **الإعدادات** واختر «طريقة حساب المعدل: موزون بعدد الوحدات» و«التقريب: جبر الكسور»، وغيّر آخر تقدير في جدول التقديرات إلى «ضعيف» إن رغبت، ثم حدّد **وحدات** كل مادة.

### حل المشكلات الشائعة
| المشكلة | الحل |
|---|---|
| فشل النشر برسالة `Branch "main" is not allowed to deploy to github-pages` | **Settings ← Environments ← github-pages ← Deployment branches and tags** ← أضف الفرع `main` (أو اختر No restriction)، ثم أعد الخطوة 17 |
| فشل النشر برسالة تفيد بأن Pages غير مفعّل | نفّذ الخطوة 16 ثم أعد الخطوة 17 |
| يظهر مربع «نسخة تجريبية» في الموقع | أسماء المتغيرات في الخطوة 15 غير صحيحة، أو لم يُعَد النشر بعد إضافتها |
| «اسم المستخدم أو كلمة المرور غير صحيحة» | اكتب اسم المستخدم (وليس بريداً) بأحرف إنجليزية صغيرة. إن نُسيت كلمة مرور المدير فنفّذ في SQL Editor: `update auth.users set encrypted_password = extensions.crypt('NewPassword123', extensions.gen_salt('bf', 10)) where email = 'admin@exam.local';` |
| «تعذر الاتصال بالخادم» بعد العطلة | توقف المشروع المجاني لعدم الاستخدام: افتح لوحة Supabase واضغط **Restore project** (مهمة الصيانة الليلية تمنع ذلك) |
| رفض الدخول وقت الذروة (Too many requests) | الخطوة 10 |
| يظهر إصدار قديم من التطبيق | اضغط «تحديث» في تنبيه «يتوفر إصدار جديد»، أو Ctrl+F5 |

### ملاحظات أمان
- مفتاح **Publishable** (أو anon) مصمم ليكون علنياً داخل المتصفح؛ الحماية الحقيقية مطبقة داخل قاعدة البيانات نفسها.
- لا تضع كلمة مرور قاعدة البيانات أو **Secret key** في الكود أو في Variables، بل في **Secrets** فقط كما في الخطوة 28.
- المستودع عام: الكود ظاهر، أما البيانات فليست كذلك. إن رغبت بمستودع خاص فإن GitHub Pages يتطلب اشتراكاً مدفوعاً، والبديل المجاني هو Cloudflare Pages.
- أي تعديل يُدمج لاحقاً في `main` يُنشر تلقائياً خلال دقيقتين، ويظهر للمستخدمين تنبيه «يتوفر إصدار جديد».

## البنية التقنية

- **الواجهة:** React 19 + TypeScript + Tailwind CSS 4 + Vite، خط IBM Plex Sans Arabic، PWA.
- **قاعدة البيانات:** PostgreSQL على Supabase — كل قواعد العمل (القفل، حالات القوائم، حدود الدرجات، الصلاحيات، سجل العمليات) مطبقة داخلها في [`supabase/schema.sql`](supabase/schema.sql).
- **التقارير:** طباعة المتصفح (PDF) و ExcelJS للتصدير.

```
src/
  lib/          الحسابات (calc)، الصلاحيات (perm)، تحليل اللصق (parse)، تصدير Excel
  data/         طبقة البيانات: Supabase + الوضع التجريبي
  components/   مكونات الواجهة، جدول إدخال الدرجات، الماستر شيت
  pages/        الصفحات
supabase/
  schema.sql    مخطط قاعدة البيانات والصلاحيات
  tests/        اختبارات الصلاحيات على PostgreSQL محلي
scripts/e2e.cjs اختبار شامل للواجهة عبر Playwright
```
