<h1 align="center">نظام إدارة اللجنة الامتحانية</h1>
<p align="center">كلية التقنيات الصحية والطبية — جامعة السراج الأهلية</p>

تطبيق ويب عربي (RTL) لإدخال درجات الطلبة وتدقيقها واعتمادها واستخراج الماستر شيت والتقارير، يعمل على الحاسوب والهاتف ويمكن تثبيته كتطبيق من المتصفح (PWA). مجاني بالكامل: **Supabase** لقاعدة البيانات وتسجيل الدخول، و**GitHub Pages** لاستضافة التطبيق.

---

## المميزات

| المجال | التفاصيل |
|---|---|
| **الأقسام** | الأقسام الخمسة مُعدّة مسبقاً: التخدير (صباحي + مسائي)، الأشعة والسونار (صباحي + مسائي)، صناعة الأسنان، صحة المجتمع (صباحي + مسائي)، التجميل والليزر. يمكن إضافة أقسام أخرى لاحقاً. |
| **الهيكل الدراسي** | سنة دراسية (2025-2026، 2026-2027 …) ← قسم ← مرحلة ← دراسة صباحية/مسائية ← فصل أول/ثاني. |
| **الطلبة** | إضافة الأسماء **بالنسخ واللصق** من Excel أو Google Sheets أو Word، مع **تسلسل ثابت لا يتغير**، واكتشاف الأسماء المكررة تلقائياً (حتى مع اختلاف الهمزة والتاء المربوطة). |
| **المواد وتوزيع الدرجة** | السعي 40% (قابل للتغيير إلى 30%)، العملي النهائي 25% (أو بدون عملي)، والامتحان النهائي يُحسب تلقائياً (35% أو 70%). يمكن تقسيم السعي إلى نظري + عملي كما في السجل الحالي (25 + 15). |
| **إدخال الدرجات** | جدول يشبه Excel: التنقل بالأسهم وEnter، **لصق عمود كامل من Excel**، حفظ تلقائي، تمييز القيم الخاطئة والناقصة، حساب المجموع والتقدير فوراً، حالات خاصة (غائب/محروم/مؤجل) بكتابة «غ» أو «ح» أو «م». |
| **فتح وغلق الإدخال** | بضغطة زر للكلية كلها أو لقسم محدد — صلاحية **مدير النظام والعميد ومعاون العميد** فقط، ومطبق على مستوى قاعدة البيانات. |
| **دورة التدقيق** | مسودة ← إرسال إلى اللجنة ← إعادة للتعديل مع ملاحظة ← اعتماد. تعديل القائمة المعتمدة يتطلب ذكر السبب ويُسجَّل. |
| **الماستر شيت** | لكل مرحلة وفصل (أو سنوي): المعدل، عدد مواد النجاح، الترتيب، الحالة العامة، إحصائيات كل مادة، الأوائل، توزيع التقديرات. |
| **التقارير** | طباعة رسمية / PDF بترويسة الكلية والشعار والتواقيع، وتصدير **Excel** بنفس تنسيق السجلات الحالية (الماستر شيت + ورقة لكل مادة). تقرير الإنجاز حسب المادة أو التدريسي. |
| **الحسابات** | حساب لكل قسم (مقرر القسم) + حساب عام (العميد) + حسابات التدريسيين واللجنة. **توليد الحسابات من داخل التطبيق** (فردياً أو جماعياً من قائمة أسماء) مع كلمات مرور مؤقتة وبطاقات دخول قابلة للطباعة. |
| **سجل العمليات** | كل إدخال وتعديل (الدرجة القديمة والجديدة)، إرسال، إعادة، اعتماد، فتح/غلق، دخول وخروج — غير قابل للحذف. |
| **الأمان** | كلمات مرور مشفرة (bcrypt)، صلاحيات على مستوى الصفوف في قاعدة البيانات (RLS)، خروج تلقائي بعد فترة خمول، إجبار تغيير كلمة المرور المؤقتة. |
| **أخرى** | وضع ليلي، تصميم متجاوب للهاتف، تثبيت كتطبيق (PWA)، نسخ احتياطي يومي مشفر، تقريب الدرجات وجدول التقديرات قابلان للتعديل. |

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| **مدير النظام** | كل شيء: الإعدادات، الأقسام، السنوات، كل الحسابات، فتح/غلق الإدخال، تعديل أي درجة. |
| **العميد** (الحساب العام) | الاطلاع والإضافة والتعديل على كل الأقسام، الإعدادات، الحسابات (عدا مدير النظام)، فتح/غلق الإدخال. |
| **معاون العميد** | كل الأقسام، فتح/غلق الإدخال، التدقيق والاعتماد، تعديل الدرجات بعد الغلق، إنشاء حسابات اللجنة والمقررين والتدريسيين. |
| **اللجنة الامتحانية** | الاطلاع على كل الأقسام، تدقيق القوائم وإعادتها أو اعتمادها. لا تعدّل الدرجات. |
| **مقرر القسم** (حساب القسم) | إدارة قسمه فقط: المواد، الطلبة، إسناد التدريسيين، إنشاء حسابات تدريسيي القسم، إدخال الدرجات، الماستر شيت. |
| **التدريسي** | المواد المسندة إليه فقط: إدخال الدرجات وإرسالها إلى اللجنة. |

> عند غلق الإدخال لا يستطيع أحد إدخال أو تعديل الدرجات سوى مدير النظام والعميد ومعاون العميد.

```bash
npm install
```

```bash

```

ثم افتح الرابط الظاهر (عادةً http://localhost:5173).

## التشغيل الفعلي (مجاناً) — خطوة بخطوة

### 1) إنشاء قاعدة البيانات على Supabase
1. أنشئ حساباً مجانياً على [supabase.com](https://supabase.com) ثم **New project** (اختر أقرب منطقة، واحفظ كلمة مرور قاعدة البيانات).
2. من القائمة الجانبية: **SQL Editor ← New query**، الصق محتوى الملف [`supabase/schema.sql`](supabase/schema.sql) كاملاً واضغط **Run**.
3. أنشئ حساب مدير النظام الأول بتشغيل السطر التالي في SQL Editor (غيّر كلمة المرور):
   ```sql
   select public.create_first_admin('admin', 'كلمة-مرور-قوية-هنا', 'مدير النظام');
   ```
4. **مهم للأمان:** من **Authentication ← Sign In / Providers** أوقف خيار **Allow new users to sign up**، لأن الحسابات تُنشأ من داخل التطبيق فقط.
5. **مهم داخل الكلية:** إذا كان التدريسيون يدخلون من شبكة إنترنت واحدة (نفس عنوان IP) فارفع حد تسجيل الدخول من **Authentication ← Rate Limits ← Sign-ups and sign-ins** (الافتراضي 30 محاولة كل 5 دقائق لكل عنوان) إلى 200 مثلاً، حتى لا يُمنع الدخول في أوقات الذروة.
6. من **Project Settings ← API** انسخ قيمتي **Project URL** و **anon public key**.

### 2) ربط التطبيق ونشره على GitHub Pages
1. في المستودع على GitHub: **Settings ← Secrets and variables ← Actions ← Variables ← New repository variable**، وأضف:
   - `SUPABASE_URL` = Project URL
   - `SUPABASE_ANON_KEY` = anon public key
2. **Settings ← Pages ← Build and deployment ← Source**: اختر **GitHub Actions**.
3. ادمج التغييرات في الفرع `main` (أو شغّل **Actions ← Deploy to GitHub Pages ← Run workflow**).
4. يصبح التطبيق متاحاً على: **https://sofianiq.github.io/Exam/**

> مفتاح `anon` مصمم ليكون علنياً داخل المتصفح؛ الحماية الفعلية مطبقة بسياسات أمان الصفوف (RLS) داخل قاعدة البيانات.

### 3) البدء بالاستخدام
1. ادخل بحساب `admin` ← **المستخدمون ← حساب جديد**: أنشئ حساب العميد ومعاون العميد واللجنة ومقرر لكل قسم.
2. يدخل كل مقرر قسم بحسابه ← **قسمي** ← يختار المرحلة والدراسة ← **قائمة الطلبة ← إضافة طلبة (نسخ ولصق)**.
3. ينشئ المقرر حسابات تدريسيي القسم (**المستخدمون ← إنشاء حسابات جماعية** بلصق الأسماء) ويطبع بطاقات الدخول.
4. يضيف المواد لكل فصل ويسند التدريسي ويحدد توزيع الدرجة (نظري + عملي، أو نظري فقط).
5. يدخل التدريسي الدرجات ← **إرسال إلى اللجنة** ← تدقق اللجنة وتعتمد ← يُستخرج الماستر شيت.
6. في نهاية فترة الإدخال يغلق معاون العميد الإدخال من **التحكم بالإدخال**.

### 4) النسخ الاحتياطي اليومي (موصى به)
الخطة المجانية في Supabase لا تتضمن نسخاً احتياطية قابلة للتنزيل، لذلك يتضمن المشروع مهمة يومية (`.github/workflows/maintenance.yml`) تأخذ نسخة **مشفرة** وتحفظها 30 يوماً في **Actions ← Artifacts**، وتُبقي المشروع المجاني نشطاً (يتوقف المشروع المجاني تلقائياً بعد أسبوع دون استخدام). أضف في **Secrets**:
- `SUPABASE_DB_URL`: من **Project Settings ← Database ← Connection string ← Session pooler** (استبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات).
- `BACKUP_PASSPHRASE`: عبارة سرية طويلة للتشفير — **احتفظ بها في مكان آمن**؛ بدونها لا يمكن فك النسخة.

**الاستعادة:**
```bash
gpg --decrypt exam-backup-2026-11-01.tar.gz.gpg > backup.tar.gz
```
```bash
tar xzf backup.tar.gz
```
```bash
pg_restore --clean --if-exists --no-owner -d "$SUPABASE_DB_URL" backup/public.dump
```
(ولاستعادة الحسابات في مشروع جديد: `pg_restore --data-only -d "$SUPABASE_DB_URL" backup/auth.dump` قبل استعادة `public`.)

إضافة لذلك يستطيع مدير النظام أو العميد تنزيل نسخة كاملة بصيغة JSON من **الإعدادات ← النسخ الاحتياطي**.

## لماذا Supabase + GitHub Pages؟

| | Supabase + GitHub Pages (المعتمد) | Firebase |
|---|---|---|
| الكلفة | مجاني | مجاني، لكن إنشاء الحسابات وإعادة تعيين كلمات المرور من داخل التطبيق يحتاج Cloud Functions (خطة مدفوعة) |
| قاعدة البيانات | PostgreSQL علائقية (كما في وثيقة المتطلبات) | NoSQL |
| الصلاحيات | تُفرض داخل قاعدة البيانات (RLS + Triggers) | قواعد أمان منفصلة |
| حدود الخطة المجانية | 500MB (تكفي عشرات السنين من الدرجات)، 50 ألف مستخدم شهرياً | — |

## البنية التقنية

- **الواجهة:** React 19 + TypeScript + Tailwind CSS 4 + Vite، خط IBM Plex Sans Arabic، PWA.
- **قاعدة البيانات:** PostgreSQL على Supabase — كل قواعد العمل (القفل، حالات القوائم، حدود الدرجات، الصلاحيات، سجل العمليات) مطبقة داخلها في [`supabase/schema.sql`](supabase/schema.sql).
- **التقارير:** طباعة المتصفح (PDF) و ExcelJS للتصدير.

```
src/
  lib/          الحسابات (calc)، الصلاحيات (perm)، تحليل اللصق (parse)، تصدير Excel
  data/         طبقة البيانات: Supabase + الوضع التجريبي
  components/   مكونات الواجهة، جدول إدخال الدرجات، الماستر شيت
  pages/        الصفحات
supabase/
  schema.sql    مخطط قاعدة البيانات والصلاحيات
  tests/        اختبارات الصلاحيات على PostgreSQL محلي
scripts/e2e.cjs اختبار شامل للواجهة عبر Playwright
```

- `scripts/e2e.cjs`: سيناريو كامل في المتصفح: إدخال ولصق، حفظ تلقائي، إرسال، إعادة، اعتماد، غلق الإدخال، لصق الطلبة، إنشاء حساب، الهاتف والوضع الليلي.
